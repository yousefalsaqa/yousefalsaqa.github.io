Vela

A personal assistant with hands. She listens for her name, talks back, drives my desktop, and keeps everything she knows about me somewhere I can read it.

Role Solo, TypeScript
Timeline Aug 2026 to present
Runtime Claude Agent SDK
Status In daily use

What she is

Vela runs on this machine, on the Claude Agent SDK, using the same OAuth credentials Claude Code already has, so there is no API key and no separate billing. Say her name and she wakes. She can open apps and files, control media, tell me what windows are open, keep an eye on something and speak up when it changes, and refer to my codebases by nickname.

The SDK gives her the baseline hands: read and write files, run shell commands, search code, fetch the web. The tool layer on top is mine.

remember / recall / forget      durable memory across sessions
list_projects / add_project     codebases by nickname
launch_app                      apps, URLs, files - knows "netflix"
media_control                   play/pause, skip, volume
list_windows                    what is currently open
watch / resolve_watch           watch something, speak up on change

Memory is an Obsidian vault

What she knows about me lives in vault/Memory as one markdown note per fact. A SQLite row is a fine place to put a fact and a terrible place to read one. As notes, I can open the vault, see everything she believes about me, correct what is wrong, and link facts together, and she reads the edit back on the next recall.

vault/Memory/
  yousef-graduated-basc-mechatronics-robotics-engineering.md
  yousef-has-used-typescript-for-his.md
  fabrication-is-aspirational-as-of-aug.md

Notes are named after the sentence rather than an id, because that name is what Obsidian links with. Frontmatter carries the kind, tags and dates, and any key she does not recognise gets written back untouched, so a plugin's metadata survives her next write. A note I write by hand with no frontmatter at all is read as a plain fact.

Projects and watches stay in SQLite. That is operational state; nobody needs to read it, and last_spoke churning through a git-tracked vault would be noise.

How a request moves through her

The order matters: she calls the tool first, then answers from what it returned. Nothing is answered from memory when the machine can be asked directly.

you    what have I got open
tool   list_windows
vela   Unreal Editor, two Chrome windows, Blender,
       and a terminal in the portfolio repo.

you    watch the build and tell me when it finishes
tool   watch
vela   Watching. I'll say something when it changes.

Architecture

Nineteen TypeScript modules, each owning one concern. The ones that earn their names:

voice.ts / listen.ts

Wake word, speech in and out, and hearing without reloading the pipeline.

memory.ts / vault.ts

The markdown vault: naming, frontmatter round-tripping, recall filtering.

desktop.ts

The hands. Windows, apps, media, files.

triggers.ts / ambient.ts

Watches and ambient state, so she can bring something up unprompted.

Where this goes

The desktop was the first body. When I move into the new place, the next one is the house: relay boards behind the light switches, and if the protocol cooperates, the dishwasher. From her side nothing changes, a switch is just one more tool with a name, and the house is the same problem as the desktop with different hands.

Her console runs in miniature on the systems index: say something to her, watch which tool fires, and watch the vault take the note.
